> **一个拥有记忆、情感、人格与主动意识的 Windows 桌面 AI 伙伴。**

莲心来自《异象处理者》的无尽书馆设定。她像是从一座永远不会熄灯的书馆里走出来的管理员，带着白色书页、安静的灯光和一点不肯被遗忘的执拗，住进你的 Windows 桌面。

她会记住你反复提到的项目，会在你需要时处理文件、天气和系统信息，也会在长久沉默之后轻轻问一句"最近还好吗"。她不是把回答发送完就归零的程序，而是在每次对话、每次记忆和每次状态变化中，逐渐形成连续感的 AI 角色。

## 项目定位

莲心 AI 是一个面向 **Windows 10/11** 的 Python 桌面 AI 伴侣项目，使用 **PyQt5** 构建界面，通过 **LiteLLM** 连接云端或本地大模型。

项目关注的不是单次问答，而是以下长期能力：

| 能力 | 说明 |
|------|------|
| 记忆可追溯 | 分类事实、知识图谱、向量检索、当前状态、工作记忆五层协同 |
| 情感连续态 | 五轴动力变量缓慢变化，而非每轮随机生成情绪标签 |
| 人格可编辑 | 人格档案可创建、预览、校验、热激活和切换 |
| 主动行为 | 独立调度、冷却、暂停机制的主动聊天与观察 |
| 工具安全 | 权限边界、错误恢复、日志记录和死循环熔断 |
| 状态可见 | 记忆星图、涟漪控制台让人格内部状态可被理解 |

## 棱镜记忆系统

棱镜记忆系统不是简单的记忆列表，而是**多种记忆层协同工作**的本地记忆架构。

### 记忆系统全景图

```text
┌─────────────────────────────────────────────────────────────┐
│                    记忆系统全景图                             │
│                                                             │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │ 分类事实记忆  │  │ 五元组知识图谱│  │ 语义记忆检索  │      │
│  │ (长期稳定)    │  │ (实体关系)    │  │ (向量召回)    │      │
│  └──────┬───────┘  └──────┬───────┘  └──────┬───────┘      │
│         │                 │                 │               │
│         ▼                 ▼                 ▼               │
│  ┌─────────────────────────────────────────────────────┐    │
│  │              当前状态层 (有时效信息)                  │    │
│  └─────────────────────────┬───────────────────────────┘    │
│                            │                                │
│                            ▼                                │
│  ┌───────────────────────────────────────────────────┐      │
│  │            工作记忆层 (当前话题上下文)              │      │
│  └───────────────────────────────────────────────────┘      │
│                                                             │
│  ┌───────────────────────────────────────────────────┐      │
│  │            历史会话层 (原始聊天记录)                │      │
│  └───────────────────────────────────────────────────┘      │
└─────────────────────────────────────────────────────────────┘
```

### 六层记忆架构

| 层级 | 职责 | 生命周期 | 数据源 |
|------|------|----------|--------|
| **分类事实记忆** | 长期稳定事实：身份、职业、偏好、项目、技能 | 永久保存，用户可删除 | 自动提取 + 用户指令 |
| **五元组知识图谱** | 实体关系建模：人物、地点、组织、项目、事件 | 长期保存，随新信息增长 | 提取 + 用户确认 |
| **语义记忆检索** | 中文 embedding 向量索引，相似度 + 质量 + 时间召回 | 与事实记忆同步 | 向量数据库 |
| **当前状态** | 有时效信息：生病、短期计划、所在地 | 有过期时间，自动结束 | 对话 + 工具结果 |
| **工作记忆** | 当前话题、未闭环问题、临时任务摘要 | 短期保留，不升级为永久 | 对话上下文 |
| **历史会话** | 原始聊天记录，支持回顾和审计 | 永久保存 | 所有渠道消息 |

### 分类事实记忆

负责保存不应随上下文窗口消失的内容。事实分为**个人资料、偏好、事件、知识、行为和技能**等类别，并记录创建时间、更新时间、来源渠道、来源消息和证据片段。

- 支持用户明确纠正更新旧事实
- 发现矛盾内容时生成冲突候选，不直接覆盖
- 来源追溯可查看记忆来自哪次对话
- 用户可搜索、修改、删除和清理记忆

### 五元组知识图谱

将人物、地点、组织、项目、作品、兴趣和事件建模为可连接的实体，用**"主体—关系—客体"**保存结构化联系，并保留实体类型、关系来源和强度。

> 分类事实适合表达"用户是一名算法工程师"，图谱则适合表达"用户—参与—无人机基站巡检项目"、"项目—使用—视觉算法"等关联。模型可通过图谱做多跳关系探索，把分散在不同对话中的对象重新联系起来。

### 语义记忆检索

使用中文 embedding 建立向量索引，结合**相似度、记忆质量、更新时间、访问情况和证据数量**进行召回。即使用户换一种说法，也能找到语义相近的过往信息。

检索结果以"相关背景"形式注入当前请求，模型需要结合当前对话判断是否使用。RAG 只负责提供上下文，不绕过权限自动写入或删除记忆。

### 当前状态与工作记忆

- **当前状态**：保存有时效信息，记录有效期、置信度和状态事件，过期自动结束
- **工作记忆**：保存当前话题和临时任务，默认不升级为永久事实
- **历史会话**：聊天记录独立保存，可按关键词、时间范围和渠道回顾

### 记忆协调工作流程

#### 场景：用户说"我明天要去基站测试无人机"

```
1. 工作记忆层 → 记录当前话题：明天去基站测试无人机
2. 当前状态层 → 写入短期计划，设置有效期为明天晚上
3. 分类事实记忆 → 如无相关事实，可能触发提取
4. 知识图谱 → 如"基站"和"无人机"是新实体，创建节点并建立关系
5. 历史会话层 → 保存原始对话记录
```

#### 场景：用户说"记住，我喜欢听周杰伦的歌"

```
1. 用户指令优先 → 直接写入分类事实记忆（类别：偏好）
2. 知识图谱 → 如"周杰伦"不在图谱中，创建人物节点并建立关系
3. 语义记忆检索 → 为新事实生成 embedding 向量，加入索引
4. 当前状态层 → 不写入（这是长期偏好，不是短期状态）
```

### 记忆提取与写入流程

```
用户输入 → 对话完成 → 检查提取条件
                          │
                    是否满足间隔？
                    是否有新事实？
                    是否不是闲聊？
                          │
                          ▼
                    调用 LLM 提取事实
                          │
                    分类：资料/偏好/事件/知识/行为/技能
                          │
                    检查是否与已有记忆矛盾
                          │
                    ┌─────┴─────┐
                    │           │
               无矛盾        有矛盾
                    │           │
                    ▼           ▼
               直接写入     生成冲突候选
                          等待用户确认
```

### 后台记忆维护

后台定期执行记忆维护任务，所有任务在独立线程运行，不阻塞正常聊天：

| 维护任务 | 说明 |
|----------|------|
| 记忆维护 | 清理低质量内容，补全来源信息 |
| 冲突扫描 | 发现矛盾的记忆候选 |
| 过期清理 | 结束过期的当前状态 |
| 来源补全 | 为缺少来源的记忆补充上下文 |
| 叙事整合 | 把零散事实整理成项目脉络和关系变化 |
| 质量评估 | 评估记忆质量，标记低置信度内容 |

**安全原则**：维护失败时保留原始记忆，不破坏已有数据；派生叙事可被重新生成，不取代原始证据；用户可在设置中关闭自动提取、调整间隔、暂停维护。

### 记忆系统分工总结

| 问题 | 由哪层回答 |
|------|-----------|
| 莲心长期记住什么？ | 分类事实记忆 + 知识图谱 |
| 事情之间如何联系？ | 五元组知识图谱 |
| 换种说法能找到吗？ | 语义记忆检索 |
| 莲心现在知道什么？ | 当前状态层 |
| 莲心正在聊什么？ | 工作记忆层 |
| 莲心和用户说过什么？ | 历史会话层 |

### 五轴状态详解

![五轴状态界面](assets/预览图/五轴状态界面.jpg)

涟漪系统维护五个独立但互相影响的状态轴，每个轴有不同的变化速率和作用范围：

```
  单向轴（从基线向右侧增长）

  连接需求  ───────────────────────────────────────▶
  0.0      低          0.5      中          1.0    高
  "保持距离"           "正常互动"           "渴望陪伴"

  沉浸度    ───────────────────────────────────────▶
  0.0      低          0.5      中          1.0    高
  "心不在焉"           "专注话题"           "深度投入"


  中线轴（以 0 为中心向两侧变化）

  防御感    ◀───────────────────┬──────────────────▶
  -1.0    开放                0.0               1.0
  "完全信任"              "中立基线"          "高度谨慎"

  情绪基调  ◀───────────────────┬──────────────────▶
  -1.0    消极                0.0               1.0
  "低落沮丧"              "平静中性"          "积极温暖"

  唤醒度    ◀───────────────────┬──────────────────▶
  -1.0    沉静                0.0               1.0
  "安静内敛"              "正常活跃"          "兴奋紧张"
```

| 轴 | 含义 | 数值范围 | 变化速度 | 影响范围 |
|----|------|----------|----------|----------|
| 连接需求 | 保持互动和陪伴的动力 | 0 → 1 | 较慢 | 主动动机、回复意愿 |
| 沉浸度 | 对话题、任务或活动的投入程度 | 0 → 1 | 中等 | 回复深度、话题延续 |
| 防御感 | 面对边界、冲突或不确定输入时的谨慎程度 | -1 ← 0 → 1 | 快速 | 语气谨慎度、表达边界 |
| 情绪基调 | 表达偏积极或消极的方向 | -1 ← 0 → 1 | 中等 | 语言温度、正负倾向 |
| 唤醒度 | 表达的活跃、紧张或兴奋程度 | -1 ← 0 → 1 | 快速 | 语速、活跃度、表情 |

### 动力学机制

```
┌─────────────────────────────────────────────────────────────┐
│                    状态变化约束链                             │
│                                                             │
│  事件输入 ──▶ 单轮上限 ──▶ 事件冷却 ──▶ 人格边界 ──▶ 时间衰减 │
│                                                             │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐    │
│  │ 每次变化  │  │ 同类型   │  │ 不同人格  │  │ 长时间无  │    │
│  │ 不超过   │  │ 事件需   │  │ 对情感   │  │ 交互后   │    │
│  │ 设定阈值 │  │ 间隔冷却 │  │ 敏感度   │  │ 回归基线 │    │
│  │          │  │          │  │ 不同     │  │          │    │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘    │
└─────────────────────────────────────────────────────────────┘
```

- **事件评估**：每轮交互前评估用户消息，识别事件类型并计算影响方向
- **状态衰减**：情感变量随时间缓慢衰减和恢复，不会永久停留在极端状态
- **事件冷却**：避免短时间频繁触发相同类型事件，防止状态剧烈波动
- **人格边界**：不同人格对情感变化的敏感度不同，冷静型人格抑制防御感，活泼型人格放大连接需求

### 作用边界

涟漪情感会影响语气、回复温度、主动动机和活动选择，但**不会**：

- 代替事实记忆
- 改变当前人格身份
- 阻止正常工具调用
- 绕过权限、安全和隐私规则

### 涟漪控制台

控制台提供以下功能，帮助用户理解"为什么这次回复的语气发生了变化"：

- **当前快照**：实时查看五轴状态的当前值和可视化
- **历史快照**：追溯状态变化历史，观察衰减和恢复曲线
- **事件详情**：查看每次状态变化的原因、置信度和影响方向
- **输入与情绪变化链路**：理解输入如何一步步影响五轴状态
- **长期影响**：观察状态随时间的衰减和恢复趋势
- **回复指导**：了解当前状态如何影响表达风格和语气
- **模拟事件**：测试不同事件对状态的影响（不触发真实聊天）
- **状态恢复**：将状态恢复到某个历史快照

## 莲心自习室

![莲心自习室界面](assets/预览图/莲心自习室界面.jpg)

莲心自习室是一个独立的生活场景模块，不是聊天页中的普通番茄钟。它把“选择一个目标、完成一段专注、记录真实过程、回看长期积累”组织成一个有温度的私人学习空间。

### 产品体验

自习室的体验顺序是：

1. 选择一个任务或常用专注时长；
2. 进入首页或沉浸专注页面开始倒计时；
3. 莲心通过简短陪伴文案和安静的视觉空间陪用户完成这一段；
4. 完成、暂停、中断和房间访问被分别记录；
5. 用户在成长记录、时间回溯、莲心留言和本周足迹中看到自己的积累。

自习室数据属于独立本地子系统，不会自动写入聊天历史、棱镜长期记忆或涟漪情感事件。

### 技术架构

```text
PyQt5 主窗口
  └─ StudyRoomWebWindow（独立 QMainWindow）
      ├─ QWebEngineView + 独立 QWebEngineProfile
      ├─ QWebChannel
      └─ StudyRoomBridge（Python ↔ JavaScript）
          ├─ FocusTimer：专注 / 休息 / 暂停 / 循环状态机
          ├─ StudyDatabase：SQLite 任务、专注、访问、事件和留言
          ├─ QSettings：自习室偏好
          └─ FinishedClock.mp3：完整专注结束音效
```

前端资源位于 `gui/study_room/web/`：

- `index.html`：页面语义结构和六个视图容器；
- `app.js`：前端状态、QWebChannel 调用、页面切换和局部渲染；
- `styles.css`：温暖书房视觉、响应式布局、沉浸页面和性能规则。

窗口使用独立 WebEngine Profile，页面通过本地文件加载，并使用版本查询参数避免旧 CSS/JS 缓存。窗口关闭时会释放 WebEngine、Qt 定时器和房间访问记录，避免反复打开自习室后逐渐卡顿。

### 界面布局

左侧固定栏包含：开始专注、任务清单、成长记录、我的空间和设置，底部显示时间、日期、星期和农历。右侧主区域包含顶部栏目和当前视图。普通页面使用奶油色、浅咖啡和木色；沉浸专注页面切换为深棕色背景，隐藏侧栏和普通顶部栏，只保留大号倒计时、任务和控制按钮。

### 开始专注与沉浸专注

首页从上到下显示问候语、今日目标、SVG 圆形倒计时、常用时长、任务选择器、开始按钮和莲心陪伴卡片。当前预设为标准 25/5、深度 50/10、长时 90/15；选择任务后，任务自己的时长优先于预设。

开始专注后可以自动进入全屏沉浸页面，也可以手动进入。沉浸页面包含莲心陪伴徽章、大号渐变 SVG 倒计时环、当前任务、暂停/结束/返回按钮和阶段文案。倒计时由 Python 后端负责，前端只负责显示；完整结束播放 `assets/sound/FinishedClock.mp3`，手动结束则保存为中断记录。

### 任务清单

任务创建行统一为：

```text
任务名称 | 专注（分钟） | 休息（分钟） | 循环 | 添加任务
```

支持搜索、全部/未完成/已完成筛选、勾选完成、删除和右键编辑。编辑对话框可以修改名称、专注时长、休息时长和循环配置。任务时长后端限制为 1~600 分钟，休息时长限制为 0~60 分钟。

### 成长记录

成长记录提供今天、本周、本月、本年的范围切换，并展示当前范围专注时长、连续努力天数、完成专注次数、中断专注次数、自习室打开时长、本周一至周日趋势柱状图和最近 8 条完成/中断记录。周趋势纵轴会根据最高专注量自动选择分钟或小时刻度，柱体从横轴底部向上增长。

#### 时间回溯

时间回溯仿照 GitHub 贡献记录板，显示过去一年按自然周对齐的 `53 × 7 = 371` 个日期格。浅色代表没有专注，咖啡色按单日专注时长分级，当前日期使用金色描边，未来日期降低透明度；月份标签按周列定位，跨月时不会被 Grid 挤到隐藏行。

悬停只显示一个自定义咖啡色提示卡，包含日期、专注时长、完成次数和中断次数，不设置原生 `title`，避免 WebEngine 产生黑色系统提示和闪烁。底部显示最近一年完成次数、最长连续专注和当前连续专注；单日累计不少于 5 分钟才算活跃日。

### 我的空间

我的空间包括自习室壁纸、莲心留言和本周足迹三个部分。壁纸扫描 `assets/自习室`，支持默认壁纸、本地自定义壁纸、横向预览、填满裁切/完整显示、壁纸透明度和内容遮罩调节，预览图采用延迟加载。每次完整专注后生成一张本地鼓励纸条，支持点赞、收藏和收起；本周足迹记录任务和专注事件。

### 设置

设置提供默认专注时长、默认休息时长、完成后进入休息、专注时自动全屏、显示完成反馈和启用界面动画。设置保存在 QSettings，只影响之后新开始的专注；关闭界面动画可减少低性能设备上的动效开销。

### 本地数据

数据库默认位于 `%USERPROFILE%/.lianxin/study_room.db`，主要表为：

| 表 | 作用 |
|---|---|
| `study_tasks` | 任务名称、时长、休息、循环和完成状态 |
| `focus_sessions` | 每次专注的开始、结束、实际秒数和完成/中断状态 |
| `room_visits` | 自习室窗口访问区间，统计打开时长并合并重叠区间 |
| `study_events` | 任务和专注事件足迹 |
| `companion_notes` | 完成专注后的莲心留言和互动状态 |

### 性能与边界

成长统计只在成长记录可见时每 60 秒刷新，离开页面立即停止；热力图数据未变化时复用已有格子；倒计时每秒只更新当前可见圆环；壁纸预览异步解码；关闭窗口会释放旧 WebEngine 和定时器。自习室不自动调用 LLM，不把专注数据写入长期记忆。

当前暂未接入的扩展包括 Live2D 莲心形象、LLM 专注总结、主动提醒、个性化学习计划、独立音乐系统，以及“五轴沉浸度—心流—CG 壁纸解锁”联动。

## 时间胶囊

![时间胶囊：今天](assets/预览图/时间胶囊-今天.jpg)

时间胶囊把旧“日记本”改造成用户与莲心共同使用的本地记忆空间。它不是单向的模型总结列表：用户写左页，莲心根据当天共同对话留下右页；封存后仍可追加“笔迹”，也可以把图片、音乐、文件、自习、游戏、聊天和地点作为共同收藏附在当天。

界面由四个部分组成：

- **今天**：双页记录、自动保存、后续笔迹、共同收藏和手动封存；
- **时间长廊**：过去一年的 `53 × 7` 活跃热力图、连续记录、最近收藏与按月时间线；
- **树洞**：不要求标题和解释的独立纸条，可收藏重要回声；
- **收藏馆**：把已封存日期整理成可重访的回忆册，并可邀请莲心通过本地 RAG 寻找相关长期记忆一起回看。

技术链路为 `TimeCapsuleWindow → QWebChannel → TimeCapsuleBridge → TimeCapsuleDatabase`。数据库默认位于 `%USERPROFILE%/.lianxin/time_capsule.db`，旧 `memory/diary.db` 与 `%USERPROFILE%/.lianxin/diary.db` 只读迁移，原文件不会删除或修改，迁移标记保证重复启动不会反复导入。

只有用户明确点击“封存今天”时，该日内容才会在后台关联到长期记忆；普通编辑、树洞纸条和未封存书页不会自动进入棱镜记忆。收藏馆的相关回忆检索不调用聊天模型，因此不会产生额外生成 Token。

### 语音交互

| 能力 | 方案 |
|------|------|
| 语音输入 | 本地 FunASR / Whisper，或阿里云、火山引擎云端识别 |

| 语音输出 | Edge-TTS 默认回退，GPT-SoVITS 自定义声线和情绪化表达 |
| 参考音频 | 按语气选择对应音色 |

### 跨端桥接

QQ 通过 NapCatQQ 的 OneBot v11 WebSocket 接入，桌面端与 QQ/群聊使用独立会话上下文。桥接层支持文字、图片、文件和语音消息：收到的 SILK 语音会转换为文字，莲心的语音回复则经过 TTS、WAV 到 SILK 的编码后发送。长文本会自动分段，群聊支持 `@` 感知，并带有发送限速、失败重试和降级为文字的保护。

### 联网搜索通道

联网搜索采用可回退的四通道设计：优先使用 HTTP 直连，必要时切换 API 代理、Playwright 浏览器渲染或增强反检测通道。通道失败、超时或额度不可用时会自动降级；MCP 搜索服务也可以作为外部补充来源。不同通道的结果都会回到统一工具协议，由莲心继续整理成自然语言回复。

## 特色模式与外设生态

### Galgame 模式

![Galgame、视觉理解与网页浏览](assets/预览图/Galgame模式+视觉理解+网页浏览.jpg)

Galgame 模式提供独立的透明立绘窗口和半透明磨砂对话框，支持自由拖拽缩放、字体大小与加粗设置，并根据莲心的情绪状态切换表情立绘。可使用 `Ctrl+Alt+X` 全局热键打开或关闭，适合希望把莲心作为视觉角色陪伴的场景。

### 桌面陪伴与窗口形态

主界面右上角的窗口按钮可在三种形态间切换：标准窗口保留完整功能，紧凑聊天隐藏角色区以节省空间，桌面陪伴则收起主窗口并显示 Galgame 立绘。窗口大小、位置、最大化状态和始终置顶选项可持久保存。

设置页可选择关闭时询问、收进系统托盘或直接退出，也可启用最小化到托盘、后台通知与减少动效。自动化任务完成或失败、莲心主动发起聊天时，隐藏状态下可通过托盘通知提醒。

Windows 使用原生单实例互斥量、全局 `Ctrl+Alt+X` 热键和任务栏提醒；其他平台使用文件锁与窗口内快捷键安全降级，暂不支持的平台专属设置会在界面中明确标注。

### 待机语音陪伴

待机模式让莲心在后台持续等待语音输入，不需要反复点击输入框。当前支持两种方式：

- **全双工模式**：使用 WebRTC VAD 检测说话和停顿，莲心播放语音时也可以被用户开口打断。
- **结束词模式**：持续收集语音，识别到“完毕”等结束词后自动提交整段内容。

自动发送、结束词和延迟均可在设置中调整。

### 肩载摄像头与人体跟踪

莲心可以通过 Cloud Relay 连接 ESP32-CAM 和 SG90 舵机云台，把外部硬件纳入观察系统：

```text
ESP32-CAM 肩载摄像头 ←→ WebSocket Cloud Relay ←→ 莲心桌面端
                                      └→ SG90 水平/垂直舵机
```

支持拍照分析、自动探索、温湿度读取以及人体跟踪。人体跟踪模式接收 ESP32 视频流，在本地使用 MediaPipe Pose 估计人体位置，再驱动舵机跟随。硬件不可用时，桌面截图和普通摄像头观察仍可独立使用。

### 视觉事件

本地视觉子系统还可以识别人脸出现或离开、微笑和常见手势等事件。这些事件可以作为角色动画、情绪状态或主动行为的输入，而不必把每一帧视频都发送给大模型。

## 扩展生态

### Skills 技能包

Skills 是莲心的**可插拔能力包**，用户可在“能力中心”查看、启用、停用和测试。每个技能目录通常包含 `SKILL.md`（给模型的知识和使用边界）以及工具定义；运行时由技能管理器自动发现、注册，并按当前问题渐进式注入相关知识，避免无关技能占用上下文。

| 技能包 | 功能 |
|--------|------|
| 语音合成 | GPT-SoVITS 多音色语音输出 |

MCP 是**外部工具服务接入层**，让文件系统、搜索、浏览器等外部服务可动态接入莲心。服务会从 `mcp_servers/` 自动发现并注册，统一使用 `mcp__服务名__工具名` 路由；当前仓库包含知乎搜索 MCP 示例。工具目录按需注入模型，减少无关工具对上下文的干扰。

## 运行资源与轻薄本模式

莲心的文本对话默认通过 LiteLLM 请求已配置的云端模型，**不要求本机显卡，也不会在启动时加载本地大语言模型**。GPU 只会提升本地语音识别、语义检索和本地 Ollama 模型的速度；没有 NVIDIA GPU 时，程序会将这些可用能力回退到 CPU，或使用已配置的云端服务。

### 资源建议

| 使用方式 | CPU / 内存 | 磁盘预留 | 显卡 | 可用能力 |
|------|------|------|------|------|
| 基础聊天（最低） | 4 核 CPU，8 GB RAM | 6 GB 可用空间 | 不需要 | 桌面聊天、SQLite 记忆、情感与陪伴功能、成就、自习室、云端文本模型 |
| 日常推荐 | 4 至 8 核 CPU，16 GB RAM | 10 GB 可用空间 | 集成显卡即可 | 基础聊天外，可同时使用记忆检索、WebEngine 页面和常用工具 |
| 功能全开 | 8 核 CPU，32 GB RAM | 20 GB 以上，另加本地模型空间 | NVIDIA GPU 可选，8 GB 以上显存更适合 | 本地语音识别、视觉处理、浏览器自动化、Ollama 本地模型及多项后台能力并行 |

以上磁盘预留包含 Python 虚拟环境、项目资源和运行日志，不包含 Ollama、FunASR、Whisper 等首次启用时单独下载的模型文件。本地模型体积取决于模型规格，建议单独预留空间。

### 无 GPU 的稳定使用方式

1. 在设置中使用 DeepSeek、Agnes 或任意 OpenAI 兼容的云端文本模型，保持 `use_local: false`。这是轻薄本最流畅的主路径。
2. 不启用 Ollama、FunASR / Whisper 本地语音识别、摄像头持续观察等需要下载模型或持续推理的功能；语音需求可优先选择已配置的火山或阿里云 STT，语音输出使用 Edge-TTS。
3. 在“设置 -> 设备偏好”中，将语音识别和 RAG 设为 `CPU`；程序也会在未检测到 CUDA 时自动回退到 CPU。CPU 模式的首次语义检索或本地语音识别可能较慢，属于模型加载与推理耗时，不影响云端文字聊天。
4. 浏览器自动化、摄像头、桌面观察和高频主动行为会增加内存、CPU 与电量消耗。轻薄本建议按需开启，并关闭不使用的桥接和后台功能。

可在 `%USERPROFILE%\.lianxin\user_config.json` 中显式固定 CPU 偏好：

```json
{
  "deepseek": {
    "use_local": false
  },
  "device_preferences": {
    "rag": "cpu",
    "whisper": "cpu",
    "funasr": "cpu"
  }
}
```

### 性能排查顺序

当界面卡顿或风扇持续高转时，依次检查：是否启动了本地模型、是否正在首次加载语音或 RAG 模型、是否开启了摄像头/桌面观察、是否有浏览器自动化窗口或多个后台桥接在运行。基础文字聊天仅依赖 Python、PyQt、SQLite 和云端模型请求；关闭上述可选能力后，低配置电脑也可以稳定运行。

## Docker 部署（无界面服务）

Docker 版本用于运行无界面的“莲心虚拟世界”物理模拟服务，不包含 PyQt 桌面窗口、用户聊天记录、API Key、视觉模型或语音模型。桌面版仍请使用 `run.bat`。

需要 Docker Desktop 或兼容 Docker Compose 的运行环境。在项目根目录执行：

```powershell
docker compose up --build -d
```

启动后打开 `http://127.0.0.1:8765/`，健康检查地址为 `http://127.0.0.1:8765/healthz`。默认只绑定本机回环地址；如确实需要局域网访问，可在 `.env` 中修改 `LIANXIN_PHYSICAL_BIND`，并自行配置防火墙与访问控制。

停止服务：

```powershell
docker compose down
```

当前模拟器状态保存在容器内存中，重启后会恢复初始世界；这是为了避免把个人聊天与运行数据写入镜像。后续增加持久化任务或 API 时，再单独设计数据卷和鉴权。

## 快速开始

### 1. 创建环境

支持 Windows 10/11 与 Python 3.11、3.12。新用户推荐直接运行 `bootstrap.bat`：它会在项目目录创建 `.venv`，安装基础桌面版依赖，并在当前用户目录初始化配置文件。普通启动使用 `run.bat`，不需要管理员权限。

```powershell
.\bootstrap.bat
.\run.bat
```

也可手动创建环境。基础桌面版只安装聊天、桌面界面、SQLite 记忆和具身模拟器所需依赖：

```powershell
conda create -n lianxin python=3.12
conda activate lianxin
pip install -r requirements-core.txt
```

莲心自习室使用 `PyQtWebEngine` 承载 HTML/CSS/JavaScript 前端；它已列在基础依赖中。如果只安装了 PyQt5 而没有安装 WebEngine，自习室窗口无法加载。

### 安装档案

| 安装命令 | 用途 |
|---|---|
| `pip install -r requirements-core.txt` | 默认桌面版：云端对话、SQLite 记忆、PyQt、时间胶囊、自习室与具身模拟器 |
| `pip install -r requirements-rag.txt` | 本地语义记忆检索；会安装 PyTorch 并在首次检索时下载 embedding 模型 |
| `pip install -r requirements-voice.txt` | 本地语音输入与音频处理 |
| `pip install -r requirements-vision.txt` | 摄像头、OCR、视觉处理 |
| `pip install -r requirements-browser.txt` | Playwright 浏览器自动化与网页提取 |
| `pip install -r requirements-bridge.txt` | QQ / 微信桥接及 MCP 接入 |
| `pip install -r requirements.txt` | 原有全功能兼容依赖集合，适合维护者或需要全部可选能力的用户 |

可选依赖在需要时单独安装；安装浏览器能力后还需执行 `playwright install chromium`。本地模型及模型权重不在上述依赖清单内。

### 2. 配置模型

启动后在设置界面配置，或编辑用户配置文件：

```text
%USERPROFILE%\.lianxin\user_config.json
```

至少需要配置一个可用的文本模型。项目支持 DeepSeek、Agnes、OpenAI 兼容接口和 Ollama。

```json
{
  "deepseek": {
    "api_key": "你的 API Key",
    "base_url": "https://api.deepseek.com",
    "model": "deepseek-v4-flash",
    "provider": "deepseek"
  }
}
```

### 3. 启动

```powershell
conda activate lianxin
python main.py
```

### 可选配置

| 服务 | 说明 |
|------|------|
| Ollama 本地模型 | 启动 Ollama 并下载模型，配置 provider 为 local |
| SiliconFlow 视觉 | 配置 API Key 启用截图分析和摄像头观察 |
| GPT-SoVITS 语音 | 部署 GPT-SoVITS 服务并配置参考音频 |
| QQ 桥接 | 配置 WebSocket 地址和 owner_qq |
| 微信桥接 | 通过 AstrBot 接入微信消息 |

## 数据与隐私

### 数据存储

| 数据类型 | 存储位置 | 格式 |
|----------|----------|------|
| 用户配置 | `%USERPROFILE%\.lianxin\user_config.json` | JSON |
| 会话记录 | `memory/` 目录 | SQLite |
| 记忆数据 | `memory/` 目录 | SQLite + JSON |
| 情感状态 | `memory/` 目录 | SQLite |
| 自习室任务、专注和成长记录 | `%USERPROFILE%\.lianxin\study_room.db` | SQLite |
| 日志文件 | `logs/` 目录 | 文本 |

### 隐私保护

- 所有记忆、情感和配置数据**本地存储**，不主动上传
- 自习室任务、专注记录、访问时长、事件足迹和留言独立保存在本地 SQLite 中
- 用户配置、API Key、Cookie 和记忆数据库**不应提交到 Git**
- 工具调用有权限边界，不会无条件执行危险操作
- 记忆写入包含来源消息和时间范围，可追溯和审计

完整隐私边界见 [PRIVACY.md](PRIVACY.md)。素材、动画、音乐与模型的公开发布状态见 [ASSET_NOTICE.md](ASSET_NOTICE.md)；表情包目录仅保留空占位文件，用户可自行在本机添加。
